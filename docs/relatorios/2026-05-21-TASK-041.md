**Conclusão de governança:** **TASK-040 cumpriu seu objetivo central.** O caminho feliz default em projetos densos não bloqueia mais a emissão da proposta. ADR-013 (DN100 proibido em lateral 5022) e ADR-014 (split por capacidade) operam em cascata como projetado: nenhum tubo Ø100mm LF aparece; apenas DN50/DN75 LF; aspersor 100% em kit homologado; PDF emitível.

## 9. Limitações

1. **Inspeção fina do mapa Mapbox WebGL** — laterais, ramais, aspersores e setores ficam no canvas, não no DOM tradicional. Validação por screenshot + observação comportamental (mesma limitação TASK-033/039).
2. **Dados internos do `IrrigationProjectResult` não expostos à UI** — `physicalColumns.length`, `max(sprinkler count)`, `lateralCapacity.hfM/velMs` por coluna não estão acessíveis via DOM ou via API HTTP (`/api/projetos/[id]` → 404). Métricas dependem da UI/serializer; testes unitários cobrem os internos (`grid-split-density.test.ts`).
3. **`window.__NEXT_DATA__` não disponível** — App Router não usa esse mecanismo. Sem acesso direto ao layout serializado.
4. **`fetch('/api/projetos/[id]')` → 404** — não há rota REST GET para o projeto; dados são server-rendered diretamente na página. Não é regressão.
5. **Console warning `"[principal] Captação dentro da faixa Y da malha"`** — registrado como H7; não bloqueia análise.

## 10. Conclusão

**TASK-040 confirmada empiricamente como sucesso operacional.** Os 4 objetivos centrais foram atingidos:

1. ✅ **Blocker técnico DN75 eliminado** — 8 colunas → 0; texto do blocker ausente da sidebar.
2. ✅ **Caminho feliz default liberado** — PDF gate retorna HTTP 200 (vs. 422 na TASK-039); proposta baixada automaticamente.
3. ✅ **DN100 continua proibido em lateral 5022** — ADR-013 preservada (0 barras Ø100mm LF).
4. ✅ **Layout construtível preservado** — 0 blockers angulares novos; 0 blockers de eixo; TASK-028 (`routeCoords`) e TASK-031 (subset filtrado) operam normalmente.

**Trade-off observado:** BOM total cresceu +R$ 51.230 (+22,6%), com o item **Ø100mm rígido em ramais (R$ 89.440)** sendo o maior driver. O crescimento é **coerente com o trade-off documentado em ADR-014** ("mais ramais via `generateSecondaries`"), mas a magnitude justifica a **TASK-042 (estratégica)** para quantificar quanto seria reduzido com alternativas arquiteturais (alimentação intermediária, redistribuição da principal, mudança de orientação automática).

**A série de validação TASK-027 → TASK-033 → TASK-039 → TASK-041 está completa.** Pela primeira vez, o projeto-tipo Barreiras (337 aspersores em 4,87 ha) produz, no caminho feliz default, uma proposta tecnicamente emitível. A regra de governança da TASK-024D (validações visuais formais) está plenamente cumprida.
