## Resumo

Aplicação da **regra oficial de construtibilidade angular** da Brasmáquinas:

- **Rede interna** (principal, ramais, laterais, trechos operacionais, registros, junções): apenas deflexões 0° e 90° permitidas. 45° é **proibido**.
- **Adutora:** deflexões 0°, 45° e 90° permitidas.

A mudança impacta o módulo de diagnóstico (`network-angle-diagnostics.ts`), o gerador de ramais (`hydraulic-connectivity.ts`) e a renderização do mapa (`ProjectMap.tsx`).

---

## Contexto

A TASK-013 introduziu `detectNetworkAngleIssues()` com `ALLOWED_DEFLECTIONS = [0, 45, 90]` para toda a rede. Antes do início desta task, o RT da Brasmáquinas confirmou a regra: **45° é exclusivo da adutora**. A rede interna opera somente com luvas (0°) e curvas/tês 90°.

## O que foi implementado

### 1. `network-angle-diagnostics.ts` — separação de regras por elemento

**Antes:** `ALLOWED_DEFLECTIONS = [0, 45, 90]` unificado para toda a rede.

**Depois:**
```typescript
export const ALLOWED_DEFLECTIONS_INTERNAL = [0, 90] as const; // rede interna
export const ALLOWED_DEFLECTIONS_ADUTORA  = [0, 45, 90] as const; // adutora
```

- `isAllowedDeflection()` usa `ALLOWED_DEFLECTIONS_INTERNAL` — `isAllowedDeflection(45) → false`.
- Diagnóstico de secondary usa `sec.coords` quando disponível: **primeiro segmento** para junção com a principal, **último segmento** para junção com a lateral.
- Mensagens de erro atualizadas: "(rede interna: apenas 90°/180° permitidos)".

### 2. `hydraulic-connectivity.ts` — campo `coords` e roteamento construtível

**`SecondaryPipe`** ganha campo opcional retrocompatível:
```typescript
coords?: [number, number][]; // polilinha da rota completa (inclui cotovelos)
```

**`routeSecondary(F, T, col, principalCoords, mPerLng)`** — função pura de roteamento:
- Calcula α = ângulo entre `perpDir` (⊥ à principal) e `lateralDir`.
- α ≈ 0° → rota reta `[F, T]` (caso padrão: principal ⊥ lateral).
- α ≈ 90° → rota em L `[F, M, T]` com cotovelo 90°; fallback à reta quando M coincide com T (caso degenerado, geometricamente válido).
- Outros α → rota reta `[F, T]`; diagnóstico emite blocker.

**`generateSecondaries()`** agora chama `routeSecondary()` e inclui `coords` e `lengthM` correto (soma dos segmentos) no output.

### 3. `ProjectMap.tsx` — usa `coords` na LineString

```typescript
// Antes:
coordinates: [s.fromCoord, s.toCoord]
// Depois:
coordinates: s.coords ?? [s.fromCoord, s.toCoord]
```

## Análise técnica: caso T2 (principal ∥ lateral)

O algoritmo `routeSecondary` foi projetado para produzir rota em L 3 pontos quando α ≈ 90°. Porém, no contexto de `generateSecondaries`, `F` é **sempre** a projeção ortogonal de `T` sobre a principal — portanto `F→T` é sempre perpendicular à principal por construção.

Quando principal e lateral são paralelas (ambas N-S), o ramal resultante (E-O) é perpendicular a ambas: junção com a principal = 90° ✓, junção com a lateral = 90° ✓. A tentativa de rota em L degenera: M coincide com T (`lenMT = 0`), e o fallback retorna a reta — que é geometricamente correta e construtível.

**Conclusão:** a infraestrutura de L-shape está correta e funcional para casos externos a `generateSecondaries`. Para os ramais gerados automaticamente, a linha reta já é sempre construtível. O teste T2 foi atualizado para refletir esse comportamento.
