## 1. Resumo executivo

A TASK-035 fecha o gap de BOM identificado na TASK-028: curvas 90° dentro das valas das laterais físicas (`PhysicalColumn.routeCoords`) **não eram contadas**. Após TASK-045B/TASK-046, `buildLateralRoute` devolve sempre 2 pontos (reta no eixo único via mediana de X) — então o estado atual produz **0 curvas** no caminho feliz. A entrega é o **mecanismo defensivo** que conta corretamente quando algum chamador futuro ou subset operacional introduzir vértice intermediário real.

**Resultado empírico:**

- **817/817 testes** (+8 novos T35-a..T35-h).
- **0 erros TypeScript.**
- **Catálogo `aspersores.ts` intocado** nesta sessão.
- **Projeto-like default (`routeCoords.length === 2`):** `curvas90LateraisCount = 0`, `curvas90LateraisSemSkuCount = 0`, nenhuma pendência nova, `totalGeral` inalterado pela TASK-035 — verificado por T35-h.
- **DN75 com curva real:** item precificado SKU `150174` (CURVA 90 LF DN75 — R$ 20,00) — verificado por T35-f.
- **DN50 com curva real:** `BOMPendingConnection { tipo: "curva_90_lateral", motivoPendencia: "sku_nao_catalogado" }`, sem reuso de SKU rígido, blocker "BOM incompleta" inclui "curva 90° lateral" — verificado por T35-g.

## 2. O que foi feito

### Função de detecção geométrica pura

**`src/lib/layout/physical-connections.ts`** — adicionado:

- `interface LateralBends90 { byDnMm: Map<number, number>; indeterminate: number }`.
- `const MIN_SEG_LEN_M = 0.01` — filtro de ruído numérico (segmentos < 1 cm são ignorados antes do cálculo angular, evitando curva falsa por ponto duplicado).
- `export function countLateralBends90(physicalColumns, centroid, toleranceDeg = ANGLE_TOL_DEG): LateralBends90`:
  - Itera `PhysicalColumn.routeCoords` com guard `length < 3` → 0 curvas para reta de 2 pontos.
  - Avalia triplas consecutivas em frame métrico local (reusa `mPerLngAtLat`, `metricVec`, `angleBetweenDeg`).
  - Critério: `|deflexão − 90°| ≤ 5°` (reusa `ANGLE_TOL_DEG` = `TOLERANCIA_ANGULAR_CONSTRUTIBILIDADE`).
  - Agrupa por `col.selecao.tubo.diametroMm`; DN ausente/inválido → `indeterminate`.

### Wiring na BOM

**`src/lib/bom.ts`** — modificado:

- Import: `CURVAS_90` (catálogo LF) e `countLateralBends90`.
- União `BOMPendingConnection.tipo` ampliada com `"curva_90_lateral"`.
- 2 campos meta novos: `curvas90LateraisCount`, `curvas90LateraisSemSkuCount`.
- **Bloco "D — Curvas 90° em laterais físicas (TASK-035)"** inserido entre B (curvas adutora) e C (kit aspersor):
  - SKU procurado **apenas em `CURVAS_90`** (família LF) — nunca em `CURVAS_90_RIGIDAS` (sem mistura de famílias/classes).
  - DN com SKU → item precificado em `BOMResult.itens`.
  - DN sem SKU → `BOMPendingConnection` com `motivoPendencia: "sku_nao_catalogado"`.
  - `indeterminate > 0` → `BOMPendingConnection` com `motivoPendencia: "dn_indeterminado"`.
- `generateProposalDiagnostics`: texto do blocker "BOM incompleta" inclui "curva 90° lateral" quando `tipos.has("curva_90_lateral")`.

### Testes

**`src/lib/layout/__tests__/lateral-bends-90.test.ts`** — arquivo novo, 8 testes:

- T35-a: rota reta (`length === 2`) → 0 curvas.
- T35-b: 1 cotovelo 90° DN75 → `byDnMm.get(75) === 1`.

- T35-g: `buildBOM` DN50 com cotovelo → `BOMPendingConnection`, blocker "BOM incompleta" cita "curva 90° lateral".
- T35-h: Projeto-like default (todas retas) → 0 curvas, 0 pendência, `totalGeral` inalterado, blocker (se existir por outro motivo) não cita curva de lateral.

## 6. Decisões tomadas

| Decisão | Alternativa descartada | Motivo |
|---------|------------------------|--------|
| Fonte única = `PhysicalColumn.routeCoords` | `Lateral.routeCoords` (trecho operacional/setorial) | 1 coluna física = 1 vala; sub-laterais compartilham vala; evita dupla contagem (item 9 do briefing) |
| SKU procurado apenas em `CURVAS_90` (LF) | Reuso de `CURVAS_90_RIGIDAS` (DN50 existe lá) | Mistura de famílias/classes (LF PN40 vs. rígido PN80) sem homologação RT — proibido pelas regras do briefing |
| DN50 sem SKU LF → `BOMPendingConnection` | Inventar SKU / aproximação | Catálogo é read-only; ausência vira pendência explícita |
| Guard `length < 3` antes da iteração | Iteração genérica com `try/catch` | Critério principal do briefing exige 0 curvas para rota reta — guard explícito |
| Filtro `MIN_SEG_LEN_M = 0,01 m` | Sem filtro | Ajuste obrigatório (item 2 do briefing) — evita curva falsa por ponto duplicado ou ruído numérico |
| Reuso de `ANGLE_TOL_DEG = 5°` | Tolerância nova | Premissa `TOLERANCIA_ANGULAR_CONSTRUTIBILIDADE` já documentada e validada |

**Sem ADR novo.** Toda a TASK-035 é cumprimento operacional da arquitetura já estabelecida por ADR-012-emenda (TASK-045B), ADR-013 (TASK-031) e da estrutura criada pela TASK-022.
