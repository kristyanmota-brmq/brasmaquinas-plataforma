## Decisões tomadas

| Decisão | Alternativa descartada | Motivo |
|---------|----------------------|--------|
| Separar detecção geométrica em `physical-connections.ts` (Camada A) | Colocar lógica diretamente em `bom.ts` | Testabilidade isolada; `bom.ts` não deve misturar geometria e resolução de catálogo |
| `BOMPendingConnection.dnMm = 0` quando DN indeterminado | Usar DN da principal como fallback | Fallback geraria item precificado incorreto; priorizar apenas o que é certo |
| `motivoPendencia: "dn_indeterminado"` como categoria distinta | Usar `"sku_nao_catalogado"` para tudo | Causas diferentes exigem ações diferentes: DN indeterminado → completar `sizedSecondaries`; SKU ausente → homologar peça |
| Filtrar `"BOM incompleta"` no optimizer (`sprinkler-grid-optimizer.ts`) | Separar categorias no retorno de `generateProposalDiagnostics` | Mudança mínima; blockers comerciais não são restrição hidráulica e não devem penalizar candidatos de layout |
| Todo projeto com aspersores gera blocker comercial | Suprimir blocker até SKU homologado | BOM incompleta não deve gerar proposta final; será removido quando TASK futura homologar tê redutor/sela de tomada |
