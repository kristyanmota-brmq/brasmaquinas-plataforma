## O que foi feito

### TASK-010C — Integração do motor geométrico à UI em modo experimental

Conectou `findBestSprinklerLayout()` à interface do `ProjectMap` de forma experimental e não-destrutiva. O fluxo padrão ("Posicionar grade 12×12 m") permanece inalterado. O motor de candidatos roda **somente por clique explícito** e só altera `layout.sprinklers` após confirmação do usuário.

**Arquivos criados:**

- `src/lib/layout/optimizer-integration.ts` — `candidateToSprinklers()`: mapeamento puro `LayoutCandidate → ProjectLayout["sprinklers"]`. Isolado para ser testável sem React. Sem solver, BOM ou setorização.
- `src/lib/layout/__tests__/optimizer-integration.test.ts` — 7 testes cobrindo toda a superfície de `candidateToSprinklers`.

**Arquivos modificados:**

- `src/app/projetos/[id]/layout-schema.ts` — `angleMode` estendido de `"auto" | "manual"` para `"auto" | "manual" | "optimizer"`. Valor `"optimizer"` marca layouts gerados pelo motor geométrico preliminar; não quebra layouts antigos (pass-through no `migrateLayout`).

- `src/components/map/ProjectMap.tsx`:
  - Imports adicionados: `findBestSprinklerLayout`, `LayoutSelectionResult`, `candidateToSprinklers`
  - Tipo local `OptimizerState` com 4 estados (`idle | running | ready | error`)
  - Estado `optimizerState` (inicializa como `idle`)
  - `useEffect` que reseta `optimizerState → idle` quando `layout.area` muda
  - `clearSprinklers` também reseta `optimizerState`
  - Callbacks: `runOptimizer` (cálculo síncrono em `setTimeout(..., 0)`), `applyOptimizerCandidate` (só chamável no estado `ready`), `dismissOptimizer`
  - Sidebar — seção Aspersores:
    - Badge "Motor" (âmbar) quando `angleMode === "optimizer"`
    - Botão "Auto" de reset também aparece quando `angleMode === "optimizer"`
    - Badge persistente: *"Layout gerado por motor geométrico preliminar — não homologado tecnicamente."*
    - Botão "Gerar candidato geométrico" (disponível sempre que `layout.area` está desenhada e `optimizerState.status === "idle"`)
    - Painel "Calculando…" com spinner quando `status === "running"`
    - Painel âmbar com 8 métricas (ângulo, score, aspersores, filling, offsets X/Y, colunas curtas, borda), `<details>` com `selectionReason`, botões "Aplicar candidato" / "Descartar"
    - Painel de erro com mensagem e botão de fechar quando `status === "error"`

## Decisões tomadas

| Decisão | Alternativa descartada | Motivo |
|---------|----------------------|--------|
| `angleMode = "optimizer"` no schema em vez de campo separado `optimizerScore?` | Campo `optimizerScore?: {...}` | Menor superfície no schema; o valor `"optimizer"` já comunica o estado; `selectionReason` não precisa persistir |
| `candidateToSprinklers()` extraída para módulo próprio | Lógica inline no callback `applyOptimizerCandidate` | Testabilidade: permite vitest sem React; isola o mapeamento para fácil revisão |
| `setTimeout(..., 0)` para `findBestSprinklerLayout` | `startTransition` do React 18 | Mais simples e portável; a função é síncrona e o ganho de UX é idêntico |
| Botão visível em ambos os estados (com/sem aspersores) | Apenas quando `!layout.sprinklers` | Permite comparar o candidato com aspersores já posicionados antes de decidir substituir |
