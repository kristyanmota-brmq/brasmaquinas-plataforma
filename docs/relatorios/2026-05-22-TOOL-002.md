### 5.2 Limitação conhecida da V1

> **Custo estimado indisponível pela telemetria atual; referência final deve ser dashboard/fatura OpenAI.**

Os campos `tokens_prompt`, `tokens_completion` e `custo_estimado_usd` no JSON canônico de `ai/gpt-review.md` são **declarados pelo próprio modelo** (não calculados server-side pelo script via campo `usage` da resposta da API). **Não é custo real.** A referência de cobrança é exclusivamente o **dashboard/fatura OpenAI**.

### 5.3 Cap acordado verbal

Cap de **US$ 0,50 por execução** acordado verbalmente. Como o modelo reportou 0, **não há base técnica para afirmar que o cap foi respeitado** — somente a fatura OpenAI poderá confirmar. Registrado aqui como limitação V1.

### 5.4 Sugestão de melhoria futura

Capturar `response.usage.input_tokens` e `response.usage.output_tokens` da Responses API (se disponível no payload de resposta) em vez de depender do modelo declarar no próprio JSON estruturado. Tarefa sugerida (não criada nesta TOOL-002):


## 6. WARN persistente — override_permitido (resposta ao Ajuste #5)

O validator emitiu o seguinte WARN em todas as execuções pós-Fase 2:

```
WARN: gpt-review.json: override_permitido declarado=true mas derivado=null — valor derivado vence
```

**Interpretação:**

- O GPT declarou `override_permitido: true` no JSON canônico.
- O validator derivou `override_permitido: null` (porque nenhuma invariante das 7 foi marcada como `violada` — não há regra terminal a aplicar).
- Conforme `ai/README.md` linhas 70-78: "valor derivado vence o valor declarado pelo GPT". Esse é o comportamento de design.
- Como nenhuma invariante foi violada, **o WARN é não-bloqueante**.

**Decisão:** WARN documentado neste relatório, mas não exige ação adicional. Override declarado pelo GPT é irrelevante neste cenário porque a decisão humana foi `aprovado_com_ajustes` sem override (override=false no decision-log).
