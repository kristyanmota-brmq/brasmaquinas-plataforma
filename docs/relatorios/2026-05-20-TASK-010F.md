## Arquitetura do fluxo de dois passos

```
Usuário clica "Otimizar layout"
  → findBestSprinklerLayout() — geométrico, 112 candidatos
  → LayoutSelectionResult { candidates, best }
  → Painel experimental: exibe best geométrico

Usuário clica "Validar hidráulica dos melhores candidatos"
  → runTopKHydraulicValidation(selectionResult, options) — Top K apenas
  → calculateIrrigationProject × K (máx 5 calls)
  → LayoutSelectionResult atualizado { best: Top K com menos blockers }
  → Painel: verde/vermelho por candidato
```

---

## Limitações conhecidas

1. **Sem desnível geodético por candidato**: avaliação usa `elevationDeltaMeters` único da opção de entrada — conservador mas não exato por candidato.
2. **Construção temporária de layout por candidato**: re-executa `buildSectorsByFlowWithColumnSplitting` e `generatePrincipalAndAdutora` por cada Top K. Custo trivial (K ≤ 5), mas não reutiliza cálculos.
3. **`jornadaHoras: 9` como placeholder**: `sizeHydraulics` não usa o valor — confirmado seguro.
4. **Pesos provisórios**: `TOP_K_HYDRAULIC_CANDIDATES` e `WEIGHT_HYDRAULIC_BLOCKER` aguardam calibração com dados de campo.
