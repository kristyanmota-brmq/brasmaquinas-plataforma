## 3. O que foi feito — implementação

### Fase 1 — Reescrita de `generateRotatedSprinklerGrid` em frame métrico local

[`src/lib/layout/sprinkler-grid.ts`](src/lib/layout/sprinkler-grid.ts) — algoritmo novo:

1. Centroide do polígono em lng/lat.
2. Converter cada vértice para frame métrico local (dx_m, dy_m × rotação plana por -angleDegrees).
3. Calcular bbox em metros do polígono rotacionado.
4. Gerar grade uniforme em metros (spacingMeters × spacingMeters).
5. Filtrar pontos via **point-in-polygon métrico** (ray-casting em coordenadas locais).
6. Rotação plana inversa (+angleDegrees) e conversão de volta para lng/lat.

`generateRotatedSprinklerGridWithOffset` agora é a base; `generateRotatedSprinklerGrid` chama-a com offset (0, 0). Mantém invariante TASK-010B.

### Fase 2 — `findOptimalGridAngle` com gate de desvio (defesa secundária)

Estendido para avaliar, para cada ângulo:

1. Gera positions via `generateRotatedSprinklerGrid` (frame métrico local).
2. Aplica agrupamento Math.round + mediana de X (espelha `generatePhysicalColumns` + TASK-045B).
3. Calcula `maxDev` por coluna.
4. **Gate dura:** candidato válido só se `maxDev ≤ TOLERANCIA_ASPERSOR_EIXO_LATERAL (0,10 m)`.
5. Entre válidos: escolhe menor bbox area.
6. Fallback: nenhum válido → menor desvio + `console.warn`.

Assinatura compatível: `findOptimalGridAngle(polygon, spacingMeters = 12)`.

## 5. Diagnóstico técnico — antes e depois

### Antes (TASK-010A → TASK-045B)

```typescript
const rotatedPoly = turf.transformRotate(polyFeature, -angleDegrees, { pivot: centroid });
const grid = turf.pointGrid(bbox, spacingMeters / 1000, { units: "kilometers" });
// pointGrid gera em graus → bbox em graus → grade NÃO uniforme em metros
```

**3 fontes de distorção métrica:**
1. `turf.pointGrid` gera pontos em **graus geográficos** (1° de lng ≠ 1° de lat em metros).
2. `turf.transformRotate` opera em coordenadas Haversine (esfera) — para ângulos não-cardinais, distorção acumulada com distância ao pivô.
3. Composição rotação → grid → rotação inversa = erros multiplicativos.

Resultado: em ângulos 1°-44° e 46°-89°, aspersores ficavam até 10+ m fora do eixo do frame métrico local.

### Depois (TASK-046)

```typescript
// 1. Centroide em lng/lat
// 2. Vértices do polígono → frame métrico local (rotação plana)
// 3. Bbox em METROS
// 4. Grade uniforme em metros (spacingMeters × spacingMeters)
// 5. Point-in-polygon métrico (ray-casting)
// 6. Rotação plana inversa + conversão para lng/lat
```

**Garantias:**
- Espaçamento real entre aspersores vizinhos = exatamente 12 m (validado por T46-3).
- Aspersores no frame local rotacionado têm `Δx` quase zero entre membros da mesma coluna (validado por T46-1, T46-2, T46-5).
- Funciona para **qualquer ângulo** (0°-89°), não apenas 0° e 45°.

## 9. Limitações

1. **Setorização precisa ser refeita** pelo usuário após "Reposicionar" — fluxo UX da plataforma; não é regressão.
2. **Positions salvas no DB precisam ser regeneradas** explicitamente para projetos antigos (clicar "Reposicionar").
3. **Mapbox WebGL** não inspeccionável via DOM — validação visual via screenshot.
4. **Polígonos extremamente patológicos** podem disparar fallback de `findOptimalGridAngle` — `console.warn` registra; blocker de eixo dispara como gate final.
