## 1. Resumo executivo

O PDF de proposta passou a exibir, no Memorial Hidráulico (Página 3), a tabela **"Dimensionamento dos ramais"** com 7 colunas: Ramal, SKU, DN, Comprimento, Velocidade, Hf, Status. Os dados vêm exclusivamente de `result.hydraulics?.sizedSecondaries` — já calculados pelo solver desde HIST-002. **Nenhum cálculo hidráulico, seleção de tubo ou validação foi adicionado** ao componente PDF.

A lógica de formatação e rotulação foi extraída para `src/lib/pdf/secondary-rows.ts` (helper puro testável), mantendo `PropostaPDF.tsx` livre de regras de domínio. Status `ok` é exibido discreto; os demais valores do enum (`velocity_exceeded`, `headloss_exceeded`, `both_exceeded`, `fallback_largest`) aparecem como warning âmbar com texto descritivo. Quando `sizedSecondaries` está vazio ou ausente, a seção é omitida — sem erro, sem warning novo.

**Resultado:** suíte de testes 817 → 826 (+9 novos T47-1..T47-9); `tsc` permanece em 0 erros; nenhum arquivo em `src/lib/layout/`, `src/lib/hydraulics/`, `src/lib/catalog/`, `src/components/`, `src/app/api/`, `docs/decisoes/`, `docs/metodologia/` alterado.

## 3. O que foi implementado

### 3.1 — Helper puro `src/lib/pdf/secondary-rows.ts`

```typescript
export interface SecondaryDisplayRow {
  id: string;
  ramalLabel: string;
  sku: string;
  dnLabel: string;       // "Ø 75 mm"
  lengthLabel: string;   // "180,5 m"
  velocityLabel: string; // "1,35 m/s"
  hfLabel: string;       // "2,84 mca"
  status: SecondaryStatus;
  statusLabel: { text: string; severity: "ok" | "warning" };
}

export function secondaryStatusLabel(status: SecondaryStatus): StatusLabel
export function mapSizedSecondariesToRows(secondaries: readonly SizedSecondaryPipe[]): SecondaryDisplayRow[]
```

Características:
- **Pura**: sem efeitos colaterais; não muta entrada (validado por T47-9).
- **Determinística**: ordenação numérica/natural por `id` (`S01, S02, S03, S10`).
- **Conservadora**: array vazio retorna `[]` sem crash.
- **Sem lógica hidráulica**: apenas formatação `toLocaleString("pt-BR")` + tradução de enum para PT-BR.

## 6. Limitações conhecidas

1. **Tabela longa em projetos com muitos ramais.** No Projeto A (TASK-046) pós-split temos ~30 sub-laterais. React-PDF gera quebra de página automática; nenhum tratamento manual foi necessário, mas o visual em projetos com 50+ ramais pode ficar denso. Não testado em projeto real.
2. **Validação visual via Playwright opcional não executada.** Briefing do approve permitiu omitir.
3. **Layout do enum `fallback_largest`.** Rótulo `"Fallback (maior DN disponível)"` é descritivo mas longo. Se necessário, pode ser encurtado em task B futura.
4. **PDF não exibe `flowM3h`.** Vazão de projeto do ramal foi omitida do PDF (escopo). Pode ser adicionada como coluna opcional em task B futura se RT pedir.
