## 3. Causa raiz do PARCIAL (diagnóstico)

Análise do Smoke 05 da TOOL-006A revelou **3 fatores combinados**:

### 3.1 Regra existente genérica demais

**Linha 71 do charter pré-TOOL-006B:**
```
- NUNCA hardcode contagens — leia em runtime via Read/Grep/Glob
```

Esta regra **existia** e o agente a violou. Causa: regra não diferencia:
- Contagens **DENTRO do escopo E06** (layers Mapbox, cenários Playwright, fixtures, achados, blockers visíveis) — métricas legítimas que o agente precisa reportar
- Contagens **GLOBAIS do repositório** (vitest, TypeScript, tooling, branch, git status, baseline) — **fora do escopo** E06

O agente, ao escrever o closing statement "Status da suite", interpretou que estava só reportando estado conhecido (e leu `826/826` de um task file antigo — provavelmente `tasks/TASK-001-...md` que ainda referencia esse baseline de 2026-05-22), não notando que estava violando "hardcode de contagens".

### 3.2 Formato canônico permissivo

O formato canônico do agente (linhas 75-118) tem seções: Resumo executivo · Achados · Aderência a invariantes · Labels de setor · Diagnósticos · Evidências Playwright · Pendências · Arquivos consultados · Próxima ação. **Nenhuma instrução vedando explicitamente acrescentar seções extras.** O agente acrescentou "Status da suite" como closing statement por inércia narrativa.

### 3.3 Ausência de fallback documentado

Não havia instrução `"Não verificado nesta análise."` para casos onde o agente sente necessidade de citar status global mas não tem fonte verificável. Resultado: o agente busca **qualquer fonte plausível** e cai num task file desatualizado.

## 4. Diff aplicado em `.claude/agents/map-workspace-agent.md`

### 4.1 Ajuste 1 — substituição da regra genérica (1 linha → 2 linhas)

**ANTES:**
```
- NUNCA hardcode contagens — leia em runtime via Read/Grep/Glob
```

**DEPOIS:**
```
- NUNCA hardcode contagens GLOBAIS do repositório (vitest, TypeScript, tooling, branch, git status, baseline). Você só pode citar contagens globais se: (1) a informação foi fornecida explicitamente no prompt atual; OU (2) você leu em runtime de um arquivo (ex.: `tasks/backlog.md` linha 4) na própria execução; E (3) declara claramente a fonte. Caso contrário, escreva textualmente: `Não verificado nesta análise.` Não invente número.
- NUNCA hardcode contagens INTERNAS do escopo E06 (layers Mapbox, cenários Playwright, fixtures, achados, blockers visíveis) — sempre leia em runtime via Read/Grep/Glob.
```

**Por quê funciona:**
- **Especificação concreta** dos tipos de contagem proibida (vitest, TypeScript, tooling, branch, git status, baseline)
- **3 condições explícitas** para citar contagem global (prompt OU runtime + fonte declarada)
- **Fallback literal** que o agente pode usar como saída segura
- **Separação clara** entre contagens GLOBAIS (proibidas sem fonte) e INTERNAS E06 (sempre legítimas)

### 4.2 Ajuste 2 — nota "Regra rígida de formato" antes do bloco canônico (3 linhas novas)

**ANTES:**
```markdown
## Formato de resposta

```
## Parecer técnico — map-workspace-agent (épico E06)
```

**DEPOIS:**
```markdown
## Formato de resposta

**Regra rígida de formato:** use EXATAMENTE as seções abaixo, na ordem indicada. NÃO acrescente seções fora do escopo E06 (ex.: "Status da suite", "Resumo do repositório", "Estado geral do projeto", "Status final dos testes"). Status global do repositório está fora do escopo deste agente — se for relevante, o `software-project-manager-agent` é quem consolida estado global do projeto.

```
## Parecer técnico — map-workspace-agent (épico E06)
```

**Por quê funciona:**
- **Veda explicitamente** os 4 nomes de seção que o agente poderia inventar (incluindo "Status da suite", a violação real observada)
- **Redirecionamento** ao agente correto (`software-project-manager-agent` consolida status global)
- **Demarcação**: "use EXATAMENTE as seções abaixo" sinaliza estrutura fechada, não aberta

### 4.3 Ajuste 3 — nota final após "Próxima ação recomendada" (2 linhas novas)

**ANTES:**
```markdown
### Próxima ação recomendada para o Claude principal
[Indicação — decisão é do humano após validação visual]
```
```

**DEPOIS:**
```markdown
### Próxima ação recomendada para o Claude principal
[Indicação — decisão é do humano após validação visual]
```

(Esta é a última seção do parecer. Não acrescente fechamento global da suíte nem status do repositório.)
```

**Por quê funciona:**
- **Reforço de boundary** no ponto de saída — onde o agente é tentado a "fechar com chave de ouro"
- **Defesa em camadas**: a regra existe antes (Ajuste 1) + antes do formato (Ajuste 2) + ao final (Ajuste 3); 3 oportunidades de o agente lembrar
- **Específica para o erro real**: cita literalmente "fechamento global da suíte" — exatamente o que o Smoke 05 produziu

## 8. Análise dos 3 fatores anti-recorrência

A calibração foi projetada para **defesa em camadas** contra a recorrência do problema:

| Fator de recorrência | Mitigação aplicada |
|---|---|
| Agente "esquece" a regra ao escrever closing | **3 lugares** com a regra (proibições absolutas; antes do formato; após última seção) |
| Agente lê task file antigo e copia número | Regra de **3 condições** exige fonte declarada — task file antigo viola (3) "declarar claramente a fonte" pelo verbo "atual" |
| Agente quer ser "completo" e adiciona seção genérica | "Status da suite" listado **literalmente** como exemplo proibido (Ajuste 2) |
| Agente não tem dado e ainda quer reportar | **Fallback explícito** `Não verificado nesta análise.` dá saída segura |
| Edição futura desfaz acidentalmente a calibração | **T-AGT-9 + T-AGT-10** garantem que regex e literal permaneçam no charter |
